Both files contain all 12 workloads, all six methods, raw timing samples, medians, compiler identification, and input fingerprints. Zero mismatches were observed. Full input/output arrays are regenerated by the executable and checked during execution; those large arrays are not stored in this repository.

The separate correctness test passed **25,224,720** output comparisons in the native-tuned six-method build and **16,816,480** in the portable four-method build. Tail checks also verify that the first element beyond the requested output length is untouched. These counts include repeated and structured inputs; they are not counts of distinct pairs or an exhaustive sweep of the input domain.

The direct binary64 quotient has a [full-domain mathematical argument](../docs/exact-division.md) under its stated assumptions. The reciprocal challenger has sampled evidence here.

## Reproduce the run

Build and run CTest using the [README](../README.md), then:

```sh
./build/mathlab_bench --output initial.json --seed 20261135 --rounds 7 --cpu-label "your CPU"
./build/mathlab_bench --output confirmation.json --seed 20261136 --rounds 11 --cpu-label "your CPU"
python tools/summarize.py confirmation.json
```

Keep timing runs sequential. Use the executable path appropriate to your CMake generator on Windows. The reporting script verifies recorded sample counts and medians; it does not independently recompute numerical outputs.

To redraw the published chart, install Matplotlib in your preferred Python environment, then run:

```sh
python tools/plot_results.py
```

The chart uses the confirmation JSON. [`manifest.json`](manifest.json) records hashes of the published numerical sources and measurements, the local validation outcome, and provenance. [Methodology](../docs/methodology.md) gives the environment and limitations.
